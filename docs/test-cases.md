# Тест-кейсы — SauceDemo

**Проект:** SauceDemo UI Automation  
**Приложение:** https://www.saucedemo.com/  
**Технологии автоматизации:** Playwright + TypeScript  

---

## Общие сведения

### Приоритеты тестирования

| Приоритет | Описание |
|---|---|
| P0 — Критический | Основная бизнес-функциональность. Ошибка блокирует критически важный пользовательский сценарий |
| P1 — Высокий | Важная функциональность. Ошибка существенно влияет на пользовательский опыт |
| P2 — Средний | Второстепенная функциональность. Ошибка имеет ограниченное влияние |


### Тестовые данные

| Логин | Пароль | Ожидаемое поведение |
|---|---|---|
| standard_user | secret_sauce | Успешная авторизация |
| locked_out_user | secret_sauce | Отказ в авторизации из-за блокировки аккаунта |
| invalid_user | wrong_password | Отказ в авторизации, аккаунта не существует |

### Общие предусловия

Если в конкретном тест-кейсе не указано иное:

1. Приложение доступно.
2. Браузер запущен.
3. Пользователь не авторизован.
4. Тестирование начинается с соответствующей страницы приложения.

## Тестирование авторизации (AUTH)

### AUTH-001 — Успешная авторизация с валидными данными

**Приоритет:** P0  
**Тип:** Позитивный  
**Предусловия:** Открыта страница авторизации.  

**Шаги:**
1. Ввести `standard_user` в поле Username.
2. Ввести `secret_sauce` в поле Password.
3. Нажать кнопку Login.

**Ожидаемый результат:**
- Авторизация пользователя проходит успешно.
- Открывается страница каталога товаров (Inventory).
- Отображается список товаров.
- URL соответствует странице каталога товаров (`/inventory.html`).

---

### CART-002 — Проверка добавленного товара в корзине

**Приоритет:** P0  
**Тип:** Позитивный  
**Предусловия:** Пользователь авторизован под учётной записью `standard_user`; в корзину добавлен как минимум один товар.

**Шаги:**

**Ожидаемый результат:**

- Цена товара соответствует цене на странице Inventory.
- В корзине отображается ожидаемое количество товаров.

---

### CART-003 — Удаление товара из корзины

**Приоритет:** P1  
**Тип:** Позитивный  
**Предусловия:** Пользователь авторизован под учётной записью `standard_user`; в корзину добавлен как минимум один товар.

**Шаги:**
1. Открыть страницу Cart.
2. Нажать кнопку Remove у выбранного товара.
3. Проверить содержимое корзины и счётчик товаров.

**Ожидаемый результат:**
- Выбранный товар удалён из корзины.
- Удалённый товар больше не отображается.
- Счётчик корзины обновлён или скрыт, если корзина пуста.

---

### CART-004 — Удаление всех товаров из корзины

**Приоритет:** P1  
**Тип:** Позитивный  
**Предусловия:** Пользователь авторизован под учётной записью `standard_user`; в корзину добавлено не менее двух товаров.

**Шаги:**
1. Открыть страницу Cart.
2. Удалить каждый товар с помощью кнопки Remove.
3. Проверить содержимое корзины.

**Ожидаемый результат:**
- Все товары удалены.
- В корзине не отображаются карточки товаров.
- Счётчик корзины отсутствует.

## Проверка бизнес-логики (BUS)

### BUS-001 — Проверка расчёта стоимости заказа

**Приоритет:** P0  
**Тип:** Позитивный  
**Предусловия:** Пользователь авторизован под учётной записью `standard_user`; в корзину добавлен как минимум один товар; открыта страница Checkout Overview.

**Шаги:**
1. Зафиксировать стоимость каждого товара.
2. Рассчитать ожидаемую сумму Subtotal.
3. Зафиксировать отображаемую сумму Tax.
4. Зафиксировать отображаемую сумму Total.

**Ожидаемый результат:**
- Subtotal равен сумме стоимости всех товаров.
- Total равен сумме Subtotal и Tax.
- Отображаемые значения соответствуют рассчитанным с учётом точности отображения валюты в приложении.

---

### BUS-002 — Проверка расчёта стоимости заказа с несколькими товарами

**Приоритет:** P1  
**Тип:** Позитивный  
**Предусловия:** Пользователь авторизован под учётной записью `standard_user`; в корзину добавлено как минимум два товара; открыта страница Checkout Overview.

**Шаги:**
1. Заполнить данные покупателя корректными значениями.
2. Нажать Continue.
3. Зафиксировать стоимость каждого товара на странице обзора заказа.
4. Рассчитать ожидаемую сумму Subtotal.

**Ожидаемый результат:**
- Все выбранные товары отображаются на странице обзора заказа.
- Subtotal равен сумме стоимости всех выбранных товаров.
- Total равен сумме Subtotal и Tax.

### BUS-004 — Сохранение содержимого корзины при навигации

**Тип:** Позитивный

## 8. Примечания и открытые вопросы

1. Точный текст сообщений об ошибках необходимо проверить непосредственно в приложении перед использованием строгих текстовых проверок в автоматизированных тестах.
2. Ожидаемое количество товаров в каталоге — 6. Это значение необходимо подтвердить при первоначальном тестировании.
3. При проверке денежных расчётов следует использовать безопасное сравнение десятичных значений или целые числа в минимальных денежных единицах, чтобы избежать ошибок вычислений с плавающей точкой.
4. Любое неожиданное поведение приложения необходимо задокументировать как дефект, а не молча изменять ожидаемый результат тест-кейса.
5. Тест-кейсы следует дополнять и актуализировать, если в ходе исследовательского тестирования будут обнаружены дополнительные требования или особенности поведения приложения.
